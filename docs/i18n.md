# Idiomas de Codeclub

La interfaz usa **i18next + react-i18next** con recursos locales. Inglés es el catálogo de referencia y el idioma de respaldo; español conserva el valor inicial de la app. No hay llamadas a proveedores de traducción ni gasto de tokens al cambiar el idioma.

## Archivos

- `src/lib/i18n.ts`: entrada pública del renderer.
- `src/lib/i18n/core.ts`: instancia, claves tipadas, hook y sincronización de preferencias.
- `src/lib/i18n/resources.ts`: registro explícito de módulos para empaquetado y validación TypeScript.
- `src/lib/i18n/locales/en/<módulo>.json` y `es/<módulo>.json`: textos de chat, archivos, navegador, terminales, extensiones, orbes, modales, menús y landing.
- `electron/i18n/`: recursos y motor nativo para tray, overlay, menú de control y notificaciones. No importa React.
- `android-companion/app/src/main/assets/i18n/`: catálogos y runtime i18next offline del WebView. Los diálogos Android siguen usando `res/values` y `res/values-es`.

## Agregar o cambiar un texto

1. Agregá la misma clave en ambos archivos del módulo. Empezá por inglés y escribí su traducción al español.
2. Usá `translate('módulo.clave', language)` para textos individuales. La clave se valida con TypeScript. Para un conjunto de etiquetas, usá `getMessages('módulo', language)`.
3. Para valores dinámicos, escribí `{{name}}` en ambos catálogos y pasá `{ name }` como tercer argumento de `translate`. Evitá armar frases con fragmentos de texto.
4. Un módulo nuevo necesita imports y entradas en `resources.ts` para ambos idiomas.
5. Ejecutá `npm run check:i18n` y `npm run test:i18n`.

```tsx
const language = useAppLanguage();
const text = getMessages('chatHistory', language);
return <button title={text.retry}>{text.retry}</button>;
```

Los callbacks instalados una sola vez pueden omitir el idioma en `translate`/`getMessages`: se consulta la preferencia vigente al ejecutarlos, evitando capturar un idioma viejo. No reinicies un efecto de permisos, conexión o formularios solamente para traducir una etiqueta.

## Preferencia y eventos

`setAppLanguage('en' | 'es')` guarda `codeclub-language` en localStorage y en el SettingsStore nativo cuando está disponible. El cambio conserva chats, contenido editable, proyectos, modelos, credenciales y permisos.

- El setter emite `codeclub:language-change` con `{ language }`. El runtime mantiene una única suscripción por ventana y actualiza i18next y `document.documentElement.lang`.
- `storage` sincroniza ventanas del mismo origen; el evento nativo `codeclub:settings-changed` con `{ key: 'codeclub-language' }` sincroniza los renderers y actualiza el tray.
- Las suscripciones se instalan en el efecto del hook y se eliminan al desmontar su último consumidor. Las lecturas nativas pendientes no pisan cambios más recientes.
- Los idiomas no compatibles vuelven al valor inicial; las claves ausentes usan inglés como respaldo.

Los textos de usuario, respuestas del modelo, páginas externas, archivos, nombres de proveedores/modelos y mensajes externos se muestran como fueron recibidos. Los valores persistidos del scheduler permanecen estables y se traducen solo al mostrarlos. Agregar un idioma no modifica la autonomía ni el alcance de las herramientas.

## Verificación

`check:i18n` comprueba módulos, claves, estructura, parámetros de interpolación y textos literales en JSX/atributos de accesibilidad. Las excepciones son marcas, unidades y nombres técnicos independientes del idioma. `test:i18n` prueba sincronización entre ventanas, preferencia nativa, recarga, interpolación, tray, etiquetas de extensiones y conservación de un borrador dentro de un modal; también ejecuta la interfaz Android con un bridge simulado.

El runtime Android distribuido es la versión UMD de la dependencia `i18next` instalada, con su licencia. Al actualizar esa dependencia, actualizá `assets/i18n/i18next.min.js` desde `node_modules/i18next/dist/umd/i18next.min.js` y repetí las pruebas. No carga scripts ni traducciones desde Internet.
